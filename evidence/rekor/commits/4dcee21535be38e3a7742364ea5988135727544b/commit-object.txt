chore(deps): npm audit fix to clear 4 transitive advisories

`npm audit --omit=dev` reported 4 advisories in the committed lockfile:

  high      fast-uri            host confusion via literal backslash
                                authority delimiter
  moderate  hono            x3  JSX cross-request context leak, cx()
                                XSS, API Gateway header de-dup
  moderate  @hono/node-server   serve-static path traversal on Windows

All arrive transitively through @modelcontextprotocol/sdk. Reachability is
low -- yaw-mcp runs as a stdio broker and does not exercise the HTTP server
paths these live on -- but the lockfile is what contributors and CI resolve,
so the vulnerable tree is what gets built from this repo. npm consumers
resolving ^1.29.0 fresh were already getting fixed versions.

`npm audit fix` alone, no --force and no package.json change: the existing
^1.29.0 range already admits SDK 1.30.0.

  @modelcontextprotocol/sdk  1.29.0  -> 1.30.0
  @hono/node-server          1.19.14 -> 2.0.12
  hono                       4.12.25 -> 4.12.32
  fast-uri                   3.1.2   -> 3.1.4
  nanoid                     3.3.12  -> 3.3.16
  postcss                    8.5.16  -> 8.5.25

@hono/node-server crosses a major version. That is not a forced override --
SDK 1.30.0 declares `"@hono/node-server": "^1.19.9 || ^2.0.5"`, so v2 is
inside the range the SDK itself supports.

`npm audit --omit=dev` now reports 0 vulnerabilities. Lint, typecheck,
build, and the full suite (2019 passing) are green on the bumped tree.

One unrelated line comes along: npm rewrites the lockfile's root `license`
from "UNLICENSED" to "SEE LICENSE IN LICENSE", matching package.json. That
is npm's own normalization -- it reappears on any plain `npm install` -- so
hand-reverting it would only make the lockfile disagree with what the
tooling generates.
